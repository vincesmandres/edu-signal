# M6.2 Real Testing Foundation

## Objetivo

Crear un harness reproducible para unit, HTTP integration, PostgreSQL/Supabase, RLS/Storage y Playwright sin cambiar autorización de producción ni afirmar resultados no ejecutados.

## Issues y arquitectura

- `package.json` separa `test:static`, `test:unit`, `test:api`, `test:db`, `test:rls`, `test:e2e`, `test:migrations` y `verify`.
- `tests/unit/validation.test.ts` y `tests/unit/migration-journal.test.ts` prueban validadores, autorización y detección de cambios de hash.
- `tests/api.integration.ts` levanta `next start` y hace requests HTTP reales; la matriz autenticada se habilita únicamente con Supabase local y fixtures.
- `scripts/local-test-env.mjs` es el guard central: valida hosts loopback y puertos `55421/55432/3000/3100`; todos los entrypoints destructivos o autenticados lo ejecutan antes de conectar/spawn.
- `supabase/config.toml`, `scripts/supabase-bootstrap.mjs`, `scripts/migration-journal.mjs` y `tests/fixtures/local-fixtures.sql` definen el entorno local. Un workdir Supabase temporal sin migrations permite aplicar Drizzle antes que policies Supabase; el journal guarda `filename+SHA256` y rechaza mismatches.
- `playwright.config.ts` y `tests/e2e/golden-path.spec.ts` usan credenciales generadas por entorno y no incluyen secretos.

## Tests y comandos

- Unit/static/typecheck: configurados para ejecutarse con Node 22 y `tsx` (la ejecución observada fue Node 24.15.0, con warning de engine).
- API: harness HTTP real, no source matching.
- DB/RLS/Storage: scripts bloquean explícitamente si faltan Docker, Supabase local o variables generadas.
- E2E: Playwright obligatorio, sin `test.skip`; `globalSetup` rechaza password/URLs no locales y regenera cuatro usuarios locales.
- `test:remote-guards` ejecuta bootstrap, cleanup, server, fixtures, preflight, DB, RLS, API, global setup y verify-local con URLs remotas ficticias; todos fallan antes de conexión.
- `npm run verify` ejecuta el gate canónico: bootstrap limpio, segunda aplicación `supabase:bootstrap:idempotent` sobre la misma base, mismatch contra journal real, guards remotos, preflight, fixtures, typecheck, lint, static, unit, build antes de API, API, DB, RLS/Storage, E2E, audit runtime high y `git diff --check`.
- Desde Supabase detenido se ejecutó `npm run verify` completo el 2026-09-23; la segunda aplicación no reinició ni limpió la base.

## Correcciones encontradas durante ejecución local

- El proyecto usa puertos locales `55421/55432/55424` y el bootstrap no toca proyectos remotos ni contenedores ajenos.
- El CLI aplicaba policies antes de Drizzle; el bootstrap usa un workdir temporal sin migrations y aplica Drizzle → Supabase sin renombrar la carpeta compartida.
- `0008_m62_rls_storage_hardening.sql` consolida el antiguo `0008/0009`, añade helpers `SECURITY DEFINER` con `search_path` fijo y `EXECUTE` sólo autenticado, lifecycle draft/active enrollment, path de cuatro segmentos y teacher submitted-own-class.
- `scripts/seed-test-fixtures.ts` limpia dependencias en orden FK, rechaza URLs no locales y genera JWTs para Teacher/Student A/B sin imprimir tokens.
- `scripts/test-migration-gate.mjs` journaliza una migración temporal en `_m62_migration_journal`, confirma la fila, rechaza el mismo filename modificado antes de SQL y elimina fila/tabla en cleanup.
- El formulario docente retenía `event.currentTarget` después de un `await`; se corrigió para que el golden path UI fuese reproducible.
- El start de actividad usa `ON CONFLICT DO NOTHING` para carreras de progreso concurrentes.

## Riesgos

- El harness API usa login HTTP real, cookie jar, spawn directo de Next, grupos de proceso y `taskkill /T` en Windows.
- Playwright ejecuta un global setup local que restablece fixtures deterministas sin imprimir credenciales; traces quedan sólo en artefactos ignorados.
- No se incluye bypass de producción ni service role en browser.
- Supabase local queda detenido después de la ejecución final; puertos 3000/3100 quedan libres y no quedan procesos Next/test.
